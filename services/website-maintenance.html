Website Maintenance & Support

Keep Your Website Reliable After Launch

A website does not become maintenance-free once it goes live. Software changes. Content changes. Integrations change. New pages get added. Third-party tools introduce updates. Performance can slowly decline. Shivantra provides ongoing website maintenance and technical support to help keep your website current, monitored and easier to operate over time.

Launch Is Not the End

A website changes even when your business does nothing

A website depends on more than the pages visitors see. Behind it may be:

  • A content-management system
  • Frameworks and libraries
  • Plugins
  • Hosting
  • Databases
  • APIs
  • Forms
  • Analytics
  • CRM integrations
  • Third-party services

Any of those can change over time.

  • A browser update can expose an issue
  • A plugin can introduce a compatibility problem
  • An expired API key can break a form
  • A new marketing script can slow the page down
  • An editor can upload a 12 MB image

Maintenance is the process of noticing and addressing those changes before they become larger operational problems.

Controlled Updates

Updating software should not mean clicking Update and hoping for the best

Updates are important for:

  • security
  • compatibility
  • bug fixes
  • platform support

But updates can also introduce incompatibilities. For websites where changes carry meaningful risk, the process should be controlled.

01

Review

Identify available updates and potential impact.

02

Backup

Create or verify an appropriate restore point before material changes.

03

Update

Apply changes in the appropriate environment.

04

Test

Check important pages and workflows such as homepage, navigation, forms, login, checkout and integrations.

05

Validate

Confirm that the website behaves correctly after the change.

06

Roll back if required

If an update introduces a serious problem, restore or revert rather than leaving the site broken.

The exact update process depends on the technology and hosting environment.

Backups & Recovery

A backup only becomes useful when it can help you recover

Backups provide an important recovery layer for:

  • Failed updates
  • Accidental content changes
  • Deployment errors
  • Data loss
  • Compromised files
  • Infrastructure failure

A backup strategy may need to consider:

  • Frequency
  • Retention
  • Database
  • Media/files
  • Application configuration
  • Storage location
  • Access control
  • Restore process

For critical websites, recovery expectations should be defined explicitly. A daily backup may be adequate for a brochure site.

It may not be adequate for a website receiving important transactions throughout the day. Backup frequency should follow the business requirement.

Monitoring

You should not have to wait for a customer to tell you the website is broken

Monitoring can help surface issues earlier. Depending on the website and support plan, monitoring may include:

Uptime

Is the website reachable?

Application errors

Are important server or application errors occurring?

Form workflows

Are business-critical forms still working?

Integrations

Are APIs or connected systems failing?

SSL

Is the certificate valid and renewing correctly?

Security signals

Are there signs that require investigation?

Performance

Has performance materially regressed?

Monitoring does not eliminate incidents.

It reduces the chance that important failures remain invisible.

Security Hygiene

Maintenance reduces avoidable security risk

No provider can guarantee that a public website will never be attacked.

But routine maintenance can reduce common avoidable risks. Depending on technology, this can include:

  • Timely software updates
  • Removing unused components
  • Secure access control
  • Credential management
  • Limiting administrator access
  • Backup
  • Security headers
  • Firewall/CDN configuration
  • Malware or vulnerability monitoring where supported
  • File permissions
  • Dependency review

For custom applications, security work may also involve:

  • Authentication
  • API access
  • Dependency vulnerabilities
  • Secrets
  • Rate limits
  • Logging

Security requirements should be proportional to the site's risk and data.

Performance Maintenance

A website can become slower without anyone deliberately changing the code

Performance often degrades gradually. Common causes include:

  • Larger images
  • New fonts
  • Marketing tags
  • Chat widgets
  • Additional plugins
  • Embeds
  • New components
  • Analytics tools

Ongoing performance support can include:

  • Core Web Vitals review
  • Image optimization
  • Script review
  • Caching
  • Frontend optimization
  • Third-party script review

Performance maintenance is particularly useful for sites receiving regular marketing changes.

Content and Small Changes

Not every website update needs a new project

Ongoing support can provide a practical way to handle smaller changes such as:

  • Update text
  • Replace media
  • Add a team member
  • Add a service
  • Create a landing page
  • Update navigation
  • Add a new form field
  • Publish a resource
  • Fix a responsive issue
  • Add a reusable section

Whether this work is included within the maintenance plan or treated separately should be defined clearly.

The objective is to give the business a reliable path for routine changes rather than accumulating a list of unresolved website issues.

Integrations Need Maintenance Too

Connected websites depend on systems outside the website

An integration that works today can fail later because:

  • API authentication changes
  • Tokens expire
  • Fields change
  • Endpoints are deprecated
  • Rate limits change
  • Another system changes its validation

Where the website depends on important integrations, support can include:

  • Monitoring
  • Error review
  • Credential updates
  • API changes
  • Mapping changes
  • Integration fixes

How Support Works

A clear support process is part of the service

01

Request

The client reports an issue or change through the agreed support channel.

02

Triage

Identify severity, scope, affected system and whether the request is maintenance, support or new development.

03

Diagnose

Investigate the cause before applying a fix.

04

Resolve

Implement the change in the appropriate environment.

05

Validate

Test the affected page, workflow or system.

06

Record

For significant changes, retain enough context to understand what was changed.

For recurring support agreements, response expectations and support channels should be defined commercially rather than implied by marketing copy.
